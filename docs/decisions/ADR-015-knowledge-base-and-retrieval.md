# ADR-015: Knowledge base and retrieval

**Status:** Accepted (Phase 8). Implements the RAG section of `docs/ai.md` and the isolation rule of ADR-006. Phase 9 (AI investigation) builds on it.

## Context

Teams keep runbooks, postmortems and how-tos. During an incident the useful one has to be found fast, and later the AI investigation needs the same material as cited evidence. It must cost nothing to run, work offline, never cross a tenant boundary, and stay useful when no AI or embedding service is available.

## Decisions

1. **Documents are Markdown, stored as chunks.** A document is split at headings (ignoring `#` inside code fences), sections over about 2 000 characters are split on paragraph boundaries with a 200-character overlap, tiny sections are merged into the next, and at most 200 chunks are kept. Every chunk's heading is the document title plus the headings above it ("Payments › Restart › Rollback"), so a result says where in a runbook it matched and a title alone is searchable. Chunking is pure and deterministic and lives in `packages/shared`.
2. **Editing re-embeds only what changed.** Each chunk stores a SHA-256 of its heading and text. On save, unchanged chunks keep their row and their vector; new ones are inserted; gone ones are deleted. Renaming a document changes every heading, so all chunks re-embed. That is the honest cost of headings carrying the title.
3. **Embeddings are asynchronous and disposable.** The API saves the document and its chunks in one transaction (with the audit entry) and queues a job; a worker embeds the chunks that lack a vector. A worker sweep every 30 s finds documents whose job was lost. A vector is written only `WHERE contentHash` still matches, so an edit made while embedding is in flight is never overwritten by a stale vector. A document is searchable by keyword the moment it is saved.
4. **The provider is an interface.** `EmbeddingProvider { id, embed(texts) }`. The default `local` provider is a deterministic feature-hashing embedder (words, word pairs and character trigrams, signed, hashed into 384 dimensions and normalised): free, offline, no setup, no dependencies. It matches shared vocabulary, related word forms and small typos. **It does not understand synonyms** ("outage" and "downtime"); that needs a trained model, so `openai` calls any OpenAI-compatible `/embeddings` endpoint (a local Ollama, or a free hosted tier) and needs a 384-dimension model such as all-MiniLM. Anthropic offers no embeddings endpoint (ADR-006). A wrong-sized vector is rejected before it reaches the database, with a message that says what to change; that failure is permanent and is not retried.
5. **Vectors never mix.** Every vector records its provider id. Search only compares vectors of the configured provider, so switching provider simply makes documents pending again and the worker re-embeds them, while keyword search keeps working throughout.
6. **Hybrid retrieval, one function, always scoped.** `retrieveKnowledge` requires an `organizationId` (checked to be a UUID; there is no unscoped variant) and every query filters by it first. It runs a keyword ranking (Postgres full-text, any query word matches, ranked by how many do) and a vector ranking (cosine, over chunks with a vector for the current provider, with a similarity floor), fuses them with reciprocal rank fusion, keeps each document's best chunk and returns the top results with a 0 to 1 score and how each was found. If the embedder fails, it answers from keywords and says so (`mode: "keyword"`); it never fails because of it. Query text only ever reaches SQL as bound parameters, and the full-text query is built from quoted tokens of letters, digits, `_` and `-`.
7. **One shared vector index, made correct for tenants.** The HNSW index covers every organization. By default a filtered ANN query takes its nearest rows across all tenants first and filters afterwards, which can leave a small organization with no results. The query therefore turns on pgvector's iterative scan (`hnsw.iterative_scan = strict_order`, pgvector 0.8, present in the project's `pgvector/pgvector:pg16` image). The index is partial (`WHERE embedding IS NOT NULL`) because Prisma ignores partial indexes; a plain one would be dropped by the next `prisma migrate dev`. Full-text search uses an expression GIN index for the same reason.
8. **Isolation is structural, as in the other domains.** Chunks reference their document by a composite foreign key `(organizationId, documentId)`, so a chunk can only belong to a document of its own organization; documents and chunks cascade with the organization. Cross-tenant tests go through the API and around it.
9. **Permissions.** `knowledge.read` for every role; `knowledge.manage` (create, edit, delete) for developers, admins and owners. Runbooks are engineering material, so support staff and viewers read.
10. **Rendering is safe by construction.** A small parser turns Markdown into data (headings, paragraphs, lists, code, quotes, rules; inline code, bold, emphasis, links) and the view renders React elements. There is no `innerHTML`; text is escaped, raw HTML is shown as text, and only `http(s)` and `mailto` links are followed (with `noopener noreferrer nofollow`). A line over 4 000 characters is shown as plain text so a hostile document cannot freeze a reader's tab.
11. **Bounded.** 500 documents per organization (enforced under a lock), 100 000 characters per document, 10 tags, 60 searches per minute per user (a limiter outage does not block search). Deleting a document is permanent; the audit log records who and what.
12. **Audited and live.** Create, edit and delete are written to the audit log inside the same transaction (title and sizes, never the body). Changes and completed indexing are announced on the real-time stream (topic `knowledge`, ADR-014), so lists, suggestions and index status update without a reload.
13. **Suggested on incidents.** `GET …/knowledge/for-incident/:id` builds a query from the incident's title, service, tags and start of its description and returns up to five runbooks. This is the same retrieval Phase 9 will hand to the investigation as citable `KB-` sources.

## Consequences

Search works out of the box with no account, key or download. Its meaning-based half is modest with the local provider and real with a proper model; the difference is one environment change and a re-embed. An organization that switches models briefly has documents that keyword search finds and semantic search does not yet. Not built, by design: importing files or URLs, revisions and history, per-document permissions, attachments, `KnowledgeChunk` retention (chunks live and die with their document).
