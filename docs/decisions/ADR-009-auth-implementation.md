# ADR-009: Authentication and tenancy implementation (differences from the Phase 0 design)

**Status:** Accepted (Phase 2). Refines ADR-005 and ADR-007.

## Context

ADR-007 chose opaque server-side sessions in HttpOnly cookies, and ADR-005 chose shared-schema multi-tenancy with layered isolation. Implementing both surfaced several concrete choices where the shipped code differs from, or fills gaps in, the Phase 0 design.

## Decisions and how they differ from Phase 0

1. **Same-origin API proxy instead of browser-to-API calls.** The browser talks only to the Next.js site; a route handler (`/api/v1/[...path]`) forwards to the API. _Why:_ the session cookie stays first-party (no credentialed CORS, no third-party-cookie problems, works regardless of API host/port), and the API can live on a private network. _Cost:_ one extra hop, and the API sees the proxy's address unless `TRUST_PROXY_HOPS` and `X-Forwarded-For` are configured. Phase 0 assumed the web and API would share a registrable domain.
2. **Organisation is chosen by URL, not by server-side session state.** Switching organisations is navigation to `/orgs/:orgId/...`; the session has no "active organisation". _Why:_ stateless, bookmarkable, and makes every request self-describing for authorization. The guard verifies membership for the organisation in the path on every request. A `nexus_last_org` cookie only remembers a convenience redirect and is never trusted.
3. **Non-members receive 404, members without permission receive 403.** Phase 0 said "404 to avoid confirming existence"; this ADR makes it precise. A foreign organisation and a nonexistent one produce byte-identical responses.
4. **Default-deny authorization via two global guards** (`SessionGuard`, `OrgAccessGuard`) plus explicit `@Public()`, `@AuthenticatedOnly()` and `@RequirePermission()` markers. A route that declares nothing is denied. _Why:_ forgetting a decorator must fail closed, not open.
5. **CSRF defence is `SameSite=Lax` plus a mandatory matching `Origin` on state-changing requests**, rather than a custom header or CSRF token. _Why:_ simple, stateless, and it also blocks login CSRF.
6. **Custom Redis fixed-window rate limiter** (about 50 lines) instead of `@nestjs/throttler`. _Why:_ we need per-account _and_ per-IP dimensions with hashed keys, fail-closed behaviour and `Retry-After`, and it is trivially unit-testable behind a store interface. _Trade-off:_ fixed windows allow a burst at a window boundary (up to twice the limit); acceptable for credential endpoints.
7. **Identifiers are UUIDs generated by PostgreSQL (`gen_random_uuid()`, v4), and tables/columns use Prisma's default camelCase names.** Phase 0 sketched UUIDv7 and snake_case. _Why:_ v4 needs no extension or application code and is non-enumerable, which is what matters for IDOR resistance; snake_case mapping would have added `@map` noise everywhere for no functional gain. Time-ordered ids can be revisited if index locality becomes a problem.
8. **Sessions have a hard cookie expiry equal to the absolute lifetime; idle expiry is enforced server-side.** Extending the browser cookie on every request would require re-issuing `Set-Cookie` on all responses for no security benefit.
9. **Registration reveals whether an email is taken** (`EMAIL_TAKEN`). Without email verification there is no way to give a neutral response and still tell the user what happened. Login does not leak this. Documented in `docs/security.md`; revisit with email delivery.
10. **Row Level Security deferred** (see ADR-005 update): application-layer scoping, composite unique keys and cross-tenant tests are in place; RLS will be added alongside the first large tenant-owned tables.
11. **Argon2 via `@node-rs/argon2`** (prebuilt N-API binaries, no install scripts or node-gyp), rather than the `argon2` package, which needs install-time native build steps that pnpm blocks by default.

## Consequences

The auth surface is small, explicit and testable, and every choice above is exercised by an automated test (unit, API integration against real PostgreSQL and Redis, or Playwright). The costs are the extra proxy hop, the fixed-window burst, and two accepted enumeration/probing risks (registration, add-member-by-email) that are listed as follow-ups.
