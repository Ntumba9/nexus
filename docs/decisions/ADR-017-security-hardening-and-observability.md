# ADR-017: Security hardening and observability

**Status:** Accepted (Phase 10). Closes the "Phase 10" items in `docs/security.md`, and records what was deliberately not done.

## Context

By Phase 9 the product's own logic was tenant-isolated, audited (for automation) and tested. What remained were the things that protect it from outside and from within: how the browser is told to treat the app, what is written down about who did what, how someone recovers or protects their own account, and how an operator sees what the system is doing. This phase also had to be honest about scope: some items on the original list cost far more risk than they remove.

## Decisions

1. **A strict, per-request Content-Security-Policy on every page.** `proxy.ts` (Next 16's replacement for middleware) generates a random nonce per request and sets `script-src 'self' 'nonce-…' 'strict-dynamic'`, `style-src` with the same nonce, `default-src 'self'`, `connect-src 'self'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'` and `frame-ancestors 'none'`; no `unsafe-inline`, no `unsafe-eval` (development only). It requires dynamic rendering, so the root layout is `force-dynamic`. The policy is a pure function with unit tests; an end-to-end test loads every main page under it with no violations and shows the browser refusing a cross-origin request and an inline handler. HSTS (two years, subdomains) and `upgrade-insecure-requests` are sent only when the request arrived over HTTPS, so `http://localhost` keeps working. Fixed headers (nosniff, DENY, referrer policy, permissions policy, cross-origin opener and resource policies) live in one constant used by `next.config.ts`.
2. **The API is locked down too.** It only ever answers JSON or text, so its CSP is `default-src 'none'; frame-ancestors 'none'; base-uri 'none'`, with HSTS and `Referrer-Policy: no-referrer`. Swagger UI defaults to on in development and off in production. A global per-IP ceiling (default 1 200 a minute) stops one client hogging the server; it is a backstop, not a security control, so it fails open if Redis is down. Health probes, metrics scrapes and the live stream are exempt. The credential endpoints keep their far stricter limits.
3. **Audit coverage.** Beyond automation, the audit log now records member added, role changed and removed, organization renamed, project and service created, changed and archived, and account events: sign-in, sign-out, sign-out everywhere, password change, reset requested and reset. Entries are written in the same transaction as the change. Account events are written into the audit log of **every organization the person belongs to** (an account is not owned by one organization, but each organization's administrators should be able to see that a member's password was reset). The request id comes from a per-request store, so entries carry the id of the HTTP request that caused them without every function being handed it. **Not recorded:** failed sign-ins. An unknown or wrong account has no organization to attribute them to, and recording them for known accounts would let anyone fill a victim organization's append-only log; they are rate limited and appear in the application logs instead.
4. **Account security.** Sign out everywhere (revokes every session). Change password (needs the current one, ends every _other_ session, cancels pending reset links). Password reset by email: the link goes to the account's own address, never in a response; the API answers identically whether or not the address has an account; a token is 32 random bytes, only its SHA-256 is stored, it works once (claimed atomically, so of several simultaneous uses exactly one wins) and expires after an hour; asking again cancels the earlier link; redeeming it ends every session and is audited. Asking is limited per address (3 an hour) and per IP. The email job carries the user id and the token, never an address: the worker looks the person up, so a job can only reach the account it names. The token is the one secret that crosses Redis, so those jobs are removed as soon as they complete. With the `log` email transport and outside production the worker prints the reset link so the flow is usable in development; it never does so in production.
5. **Structured logs and correlation.** The API logs one JSON object per line in the same shape as the worker, through a logger that attaches the request id, person and organization of the request being served and passes every message and stack trace through the secret redactor. One line per finished request (method, route template, status, duration; never bodies, cookies, query strings or addresses). The request id travels into the jobs a request causes (embedding, investigation, reset email), and the worker's job log lines carry it, so a request can be followed from the browser through the API into a worker.
6. **Metrics without a dependency.** A small registry renders the Prometheus text format: request counts and latency by **route template** (never a URL with ids, so the series count stays bounded, and each metric is capped at 500 series), open real-time streams, process gauges, and in the worker jobs by queue and outcome, job duration and queue depth. `GET /metrics` on the API and on the worker's health port does not exist unless `METRICS_TOKEN` is set (404), then needs it as a bearer token, compared in constant time. A session cookie is not a substitute.
7. **Tenant isolation is guarded by a test of the live catalog.** A database integration test reads the real schema and fails if a table lacks `organizationId` without being on a reviewed exceptions list (and says why each is there), if a tenant table is not anchored to an organization by a foreign key, or if any foreign key between two tenant tables omits `organizationId` and could therefore point across tenants. It was checked by creating three violations and confirming each is caught.
8. **Supply chain.** CI fails on any known high or critical advisory in production dependencies (`pnpm audit --prod --audit-level high`), and Dependabot opens grouped weekly updates. Two transitive advisories found and fixed with `pnpm.overrides` in the root `package.json`: `multer` (pulled in by `@nestjs/platform-express`; this API accepts no uploads, but it is patched) and `deepmerge-ts` (inside Prisma's own CLI tooling). Prisma, the build and the API were re-verified with them.

## Deliberately not done

- **Row Level Security.** ADR-010 said it needs a non-superuser role and per-transaction session variables. Doing it properly means every query in the API (hundreds, including raw SQL, interactive transactions and public routes that derive the organization from a record) must run with the organization context set, and the workers, which legitimately work across organizations, must use a different role. Retrofitting that carries a high risk of regressions across a codebase with 500+ integration tests, for a protection that duplicates composite foreign keys, org-scoped queries, the catalog test above and per-route tests. Anything short of all of it would look protective while enforcing nothing. **Rollout plan if it is wanted:** a `nexus_app` role without `BYPASSRLS`; policies `organizationId = current_setting('app.organization_id')::uuid` on every tenant table; one wrapper that opens a transaction, sets the variable from the verified tenant context and hands the transaction client to services; workers on a separate `nexus_worker` role; roll out table by table behind the catalog test.
- **MFA (TOTP) and email verification.** Both are real work with real risk (recovery codes, enrolment, lockout handling; deliverability and abuse of the verification path) and neither is needed to demonstrate the security model. Registration still reveals whether an email is taken (rate limited); adding verification would remove that.
- **OpenTelemetry.** Traces would add a large dependency tree and a collector to run. Structured logs with request ids plus Prometheus metrics cover the questions an operator asks first; spans are the next step if the system is split across more services.
- **Failed-login auditing**, for the reason in decision 3.

## Consequences

The browser now refuses injected script even if XSS is found, sessions can be ended by their owner, the audit log answers "who changed this and from where", an operator can scrape health and latency, and a future table cannot quietly weaken tenancy. The costs: every page renders per request (no static pages), and a page that needs inline script must be given the nonce rather than an exemption.
